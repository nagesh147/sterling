# A74 — TrueData Response-Schema Verification and Fixture Contract

TrueData is the sole research market-data authority. Zerodha Kite is the trading/execution/position authority.

The repository TrueData Postman collection verifies request forms for getticks, getAllTicks, getbars, getAllBars, getAllBarsforMin, getlastnbars, getlastnticks, getSymbolOptionChain, getSymbolExpiryList, gettradedsymbols, getbhavcopy and corporate-action endpoints. It explicitly demonstrates 1-second and tick request forms, so the architecture is not minute-only.

Request evidence does not establish complete response semantics. Unknowns remain UNKNOWN.

## Fixture contract

Each endpoint requires an immutable fixture containing endpoint, request parameters, retrieval time, raw response, encoding, provider event timestamp when present, documentation reference and schema status. Credentials must never be committed.

Required classes: VALID, EMPTY, MISSING_FIELD, MALFORMED, OUT_OF_ORDER, DUPLICATE, BOUNDARY_TIME, and CORRECTION_OR_REVISION when provider behavior is evidenced.

## Canonical boundary

TrueData raw response -> provider parser -> validated observation -> canonical market event.

Every canonical value must trace to endpoint -> provider field -> deterministic transformation -> fixture. No source value means no fabricated value.

## Field contract

For every strategy-consumed field record canonical name, provider endpoint/field, semantic definition, datatype, unit, precision, timestamp association, transformation, missing behavior, validation rule, fixture and entitlement. Unknown semantics block strategy-critical use.

## Time

Preserve provider_event_time, provider_request_time and adapter_ingest_time separately. Historical chronology uses provider event time; ingest time must never replace it in features, labels, returns, probabilities or decisions.

Timezone, clock precision, sub-second semantics, ordering guarantees, late-arrival behavior and correction semantics remain UNKNOWN until verified.

## Resolution

TICK, SECOND and MINUTE resolutions are permitted. No one-minute restriction is frozen. Aggregation must be causal: only events with event_time <= decision_cutoff may enter a decision state.

## Units

Verify price, quantity, volume, open-interest units, percentage representation and precision before mathematical use. Unknown units cannot enter unit-dependent calculations.

## Missing data

Preserve ABSENT, NULL, MALFORMED, OUT_OF_ORDER, DUPLICATE, UNAVAILABLE and UNKNOWN. The raw adapter must not silently forward-fill, back-fill, zero-fill, interpolate, substitute nearest values or delete rows.

## Invariants

V1 provenance; V2 temporal causality; V3 timestamp validity; V4 unit safety; V5 schema integrity; V6 secret isolation; V7 no fabrication; V8 deterministic canonicalization; V9 TrueData-only research data and Kite-only trading state.

## Fail closed

Reject unknown required columns, invalid timestamps, ambiguous timestamp semantics, invalid required numeric values, inconsistent row widths, unsupported encoding, corrupted responses, unverified strategy-critical units and schema contradictions. HTTP success is not sufficient evidence of valid research data.

## Frozen

TrueData research boundary; fixture-first verification; raw-response preservation; provenance; timestamp separation; fail-closed validation; tick/second/minute availability; Kite execution boundary.

## UNKNOWN / TODO

Exact response columns, field semantics, units/precision, timezone guarantees, ordering guarantees, late-arrival behavior, correction/revision behavior, retention/entitlement limits and schema-version policy.
